# 미라 1명 승인용 시안 — 2026-09-27

사용자가 전체 캐릭터 작업 전에 한 명을 먼저 보고 판단하도록 요청한 작업이다. 이후 **“테스트하게 적용해봐”** 지시에 따라 미라의 새 일러스트·네 방향 대기·8프레임 걷기를 게임에 시험 적용했다. 전체 화풍의 최종 승인이나 모든 동작의 완성을 의미하지 않는다. 다른 23종은 기존 네 방향 아트를 사용한다.

## 열기

- 개발 서버: `http://localhost:5173/character-preview/mira/index.html`
- 서버 없이: `public/character-preview/mira/index.html`을 브라우저로 연다.
- 원본과 좌표 명세를 다시 복사: 프로젝트 루트에서 `node scripts/pack-mira-preview.mjs`.
- 게임 테스트: 홈 → **초반 마을 테스트** → 주민 → 미라. Q/E로 지도 회전.
- 게임용 재패킹: `python scripts/mira_runtime.py art-source/pixel-characters/prototypes/mira-v2/runtime-pack.json`.
- 상위 `pack-pixel-characters.py`도 미라의 `runtimePrototype` 명세를 호출하므로 전체 재패킹 시 새 시안을 보존한다.

## 게임 시험 적용 범위

실행용은 `public/assets/pixel-characters/mira/`다. 128px 셀, 13열 × 4행, 1664×512 RGBA. 열 0은 새 방향별 대기, 1~8은 새 걷기, 9~12는 기존 운반/작업이다. 작업·공격·줍기·내려놓기는 기존 미라 포즈를 계속 조합한다. 기존 실행용 아틀라스와 앵커를 `legacy-actions.png`, `legacy-frames.json`으로 보존했다. 미라 이외의 아트는 교체하지 않았다.

`runtime-pack.json`은 원본 참조·발 기준선·크기·기존 동작 열을 관리한다. 패커는 원본 RGB를 다시 그리지 않고, 가장자리와 연결된 크림색 배경을 알파로 분리한 뒤 자르기·정렬·최근접 축소만 수행한다. 새 36개 대기/걷기 셀은 동일한 발 기준점을 사용한다. 게임과 주민 패널은 `frames.json`의 동작별 열 목록을 읽는다. 캐릭터 ID와 저장 형식은 유지된다.

## 방향

사용자 두 번째 참고의 큰 머리와 읽기 쉬운 팔다리를 갖춘 약 4등신 SD를 목표로 한다. 세 번째 참고처럼 같은 인물의 고유 픽셀 일러스트를 제공한다. 미라의 갈색 포니테일, 청록 작업복, 크림색 상의, 가죽 공구 벨트와 황동 장식은 기존 정체성에서 이어왔다. 비율·얼굴·화풍의 최종 판정은 사용자에게 남아 있다.

`study.png`는 첫 일러스트/스타일 시트다. 이 시트의 작은 동작 행은 재생에 사용하지 않는다. `walk.png`는 이전 E 방향 8개 걷기 포즈를 보존한 원본이다. 새 `walk-quarter.png`는 SW/NW/NE/SE 각 8개, 총 32개 걷기 포즈다. `motions.png`는 이전 대기·방향·작업·인사·상자 상호작용 원본이다. 최신 미리보기에서는 걷기 32개, 방향 4개, 대기·작업·인사·상자 각 8개로 총 68개 포즈를 사용한다. `네 방향 함께`로 보행을 나란히 보고, Q/E로 현재 걸음의 프레임을 유지하며 방향을 바꿀 수 있다.

## 프레임 관리

원본 PNG는 이미지 생성 도구 결과를 그대로 복사했다. PNG의 픽셀을 코드로 다시 그리거나 보간해서 새 작화로 주장하지 않는다. 브라우저는 `pack-manifest.json`의 원본 좌표에서 그림을 가져와 표시한다. 프레임별 발 기준점과 클립 공통 크기를 사용하고, 웅크린 그림의 높이를 억지로 늘리지 않는다. 원본, 명세, 실행용 이미지/좌표는 `scripts/pack-mira-preview.mjs`로 함께 관리한다.

미리보기는 `requestAnimationFrame`의 경과 시간으로 위치를 갱신한다. 위치 갱신은 포즈 교체와 별개이며 재생 속도를 바꾸면 두 속도가 함께 변한다. 선택한 네 대각선 방향으로 이동한다. 게임용은 별도 투명 아틀라스를 사용한다.

게임의 이동 코드도 별도로 수정했다. `character-movement.js`가 주민·경비·습격자의 경로에서 한 틱의 남은 이동량을 다음 구간에 넘긴다. 꺾이는 지점을 건너뛰거나 막힌 다음 타일로 들어가지 않는다. `pixel-characters.js`는 실제 경로 이동 거리로 보행 프레임을 진행해 속도 변경 시 위상이 건너뛰지 않도록 한다. 누적 거리는 WeakMap에만 보관하므로 저장 형식·키는 바뀌지 않는다.

## 남은 사항

- 걷기는 네 대각선 방향의 초안을 추가했다. 대기·작업·인사·상자 행동은 E 방향의 이전 시안이며, 네 방향 전체 행동 조합은 아직 없다.
- 방향 보기는 90도 간격 네 원화 재생이다. 현재 시스템은 자유 회전용 중간 작화를 요구하지 않는다.
- 공격·피격·사망, 작업별 도구 행동, 별도의 운반 보행은 없다.
- 새 걷기 원화는 재생성과 수정 요청을 거쳤지만 반대쪽 다리가 앞으로 나오는 접지 자세가 여전히 충분히 구별되지 않는다. 포즈 간 얼굴·머리카락·실루엣 변화와 보행 리듬도 더 정리해야 한다. 포즈 수나 이동 코드 검사만으로 자연스러운 모션 완성을 주장하지 않는다.
- 검토용 원본은 크림색 배경을 보존하며, 게임 실행용만 투명 배경으로 패킹했다.
- 주민 패널과 3D 월드의 미라에 새 대기·걷기·일러스트를 적용했다. 기존 운반·작업으로 넘어갈 때 비율/화풍 차이가 남는다.
- 타일 경계 이동량 손실은 수정했다. 기존 아트의 3포즈 걷기와 프레임별 비례 차이는 남아 있다. 기기 성능에 따른 프레임 저하까지 해결했다는 뜻은 아니다.
