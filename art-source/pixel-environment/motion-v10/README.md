# 운송·상하차 동작 원본

`rig.json`은 기존 `completion-v8` 운송 그림의 바퀴·말 다리·노·프로펠러 위치와 항구 화물 좌표를 기록한다. 새로운 본체 원화를 그린 것이 아니라 기존 픽셀 부품을 움직여 8프레임으로 구운 것이다. 방향 행은 SE → NE → NW → SW, 셀은 192px이다. 첫 프레임은 원래 운송 그림과 픽셀 단위로 같다.

재생성 순서:

```sh
node scripts/pack-pixel-environment.mjs
node scripts/pack-environment-motion.mjs
```

두 번째 명령은 이 폴더의 PNG, 실행용 PNG, 상위 `pack-manifest.json`과 실행용 `frames.json`을 함께 갱신한다. 패커는 기존 본체 PNG를 입력으로 사용한다. 등록된 `prepacked` 항목은 첫 번째 명령으로도 그대로 복사된다.

- 말 다리는 위쪽 접점을 중심으로 움직이고, 바퀴·증기선 외륜은 테두리 안에서 회전한다. 프로펠러는 날개별 영역과 고정 축을 사용하며 짧은 잔상을 남긴다. 원화에 가려진 엔진 부분을 투명하게 뚫지 않는다.
- 뗏목은 노를 움직인다. 선박의 물결은 런타임에서 실제 이동 중에만 생긴다. 일반 화물선·나룻배의 본체 프레임은 같고 물결이 움직인다.
- 항구는 본체와 화물·고리를 분리하고 로프는 런타임에서 잇는다. 크레인이 있는 바다 연안항·강 항구·극지 항에 적용한다. 극지 항의 북서 시점은 화물이 지붕에 가려져 인양 변위를 생략한다. 호수 항에 없는 크레인을 추가하지 않는다.
- 실제 이동 거리가 프레임을 진행시킨다. 계류 항공기는 정지 상태를 유지하며 미리보기의 **이동 동작**으로 프로펠러를 비교할 수 있다.

런타임 연결은 `pixel-motion-data.js`, `pixel-environment.js`, `logistics-visual-events.js`에 있다. 검사는 `tests/environment-motion.mjs`, 실제 비교 화면은 `/art-preview.html`이다.
