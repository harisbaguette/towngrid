# 온라인 순위와 서버 저장

홈이나 게임 메뉴의 **온라인·서버 저장**에서 계정을 만든다. 계정·저장·순위·상회는 접속한 서버에 속한다. 로컬 실행기의 서버는 이 컴퓨터에서만 사용할 수 있으며 인터넷에 공개된 서비스가 아니다.

## 플레이

- 이름은 3~24자, 비밀번호는 12~128자다. 가입할 때 보이는 복구 코드를 보관한다. 비밀번호를 잊으면 이름과 복구 코드로 바꿀 수 있고, 사용한 코드는 폐기된다.
- **현재 마을 서버에 저장**은 캠페인 한 개를 보관한다. 다른 기기에서 같은 서버에 로그인하고 **서버 저장 불러오기**를 누르면 이어한다. 불러오기 전에 현재 로컬 저장을 백업하고, 불러온 게임은 일시정지한다.
- 다른 기기에서 먼저 저장했다면 덮어쓰기를 막는다. **새로 확인**으로 최신 시각을 확인한 뒤 불러오거나 현재 게임을 다시 저장한다. 서버 저장은 수동이다. 평소 자동 저장은 브라우저에 남는다.
- 산업 도전을 마친 뒤 **사람끼리 순위 → 완료한 도전 기록 제출**을 누른다. 서버가 건설·생산·운송 기록을 재실행해 점수를 계산한다. 점수 내림차순, 소요 시간 오름차순, 먼저 제출한 순으로 정렬한다. 같은 도전에서는 개인 최고 기록만 남는다.
- 상회는 최대 20명이다. 초대 코드로 참여하며, 같은 도전의 개인 최고 점수를 합산한다. 기록은 첫 제출 당시 상회에 귀속된다. 탈퇴·이적해도 기존 기록을 다른 상회로 옮길 수 없다. 상회장이 해산하면 상회 순위에서 빠진다.

이전 형식의 도전은 로컬로 계속 플레이할 수 있다. 서버 순위는 `practice-v2-*`와 `weekly-v2-*`의 처음부터 기록된 게임만 받는다. 종료 뒤의 점수 조작이나 임의 자금·재고는 인정하지 않는다. 이 검증은 자동 플레이나 여러 계정의 사용 여부까지 판정하지 않는다. 같은 마을을 여러 사람이 동시에 조작하는 기능은 없다.

## 서버 운영

Node.js 24 LTS를 사용한다. `npm run dev`는 게임과 로컬 API를 함께 실행한다. 기본 데이터 파일은 `work/community.sqlite`다. 별도 API 서버는 다음처럼 실행한다.

```powershell
$env:TOWNGRID_ORIGIN = 'https://game.example.com'
$env:TOWNGRID_DATABASE = 'C:/TownGridData/community.sqlite'
npm run community
```

API는 기본 `127.0.0.1:8788`에서 듣는다. `HOST`·`PORT`로 변경할 수 있다. 실제 게임 주소를 `TOWNGRID_ORIGIN`에 넣고 HTTPS 프록시에서 같은 주소의 `/api/community/` 요청만 이 API로 전달한다. `Origin`, `Cookie`, `Set-Cookie`, JSON 본문을 보존해야 한다. HTTPS 주소에서는 세션 쿠키에 Secure를 적용한다. 로그인은 7일 동안 유지된다.

기존 Workers 프런트엔드 빌드에는 이 Node API가 포함되지 않는다. 인터넷 서비스에는 API를 계속 실행할 서버, 영구 저장 공간, HTTPS 및 같은 출처의 경로 연결이 필요하다. 현재 프로젝트에는 공개 운영 서버 주소가 설정되어 있지 않다.

백업할 때 API와 개발 서버를 모두 종료하고 데이터 파일 및 같은 이름의 `-wal`·`-shm` 파일이 남아 있으면 함께 복사한다. 복원도 서버를 끈 상태에서 수행한다. 데이터 파일에는 계정 정보와 비공개 게임 저장이 들어 있으므로 공개 파일 경로에 두지 않는다. 여러 서버 인스턴스가 같은 파일을 동시에 운영하는 구성은 지원하지 않는다. IP 단위 요청 제한이 있으므로 프록시 뒤의 이용자는 같은 제한을 공유한다.

산업 도전 규칙을 바꾸면 새 버전의 ID를 사용한다. 기존 ID의 초기 조건·생산 규칙을 바꾸면 저장해 둔 플레이 기록을 같은 결과로 재현할 수 없다.
