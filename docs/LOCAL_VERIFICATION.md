## 이후 변경: 초반 픽셀 건물 5종

창고·주민 주택·우물·밀밭·벌목장을 네 방향×네 상태로 추가하고 시작 화면의 **초반 마을 테스트**에 연결했다. Windows / Node v22.18.0, 기존 의존성으로 다음 검사를 통과했다.

- `npm run typecheck`, `npm test`, `npm run build`.
- 헤드리스 환경 검사: 6종 건물의 상태·방향 UV·PNG 규격, 12개 플레이 가능 국가의 테스트 마을 생산·운반, 기존 저장 형식으로 복원, 보통 새 게임의 빈 땅 유지.
- 기존 브라우저 검사: 최초 3종 샘플, 네 방향 카메라·Q/E·마우스·터치·확대, 건설 미리보기, 투명 픽셀 선택, 나무 고갈, CPU 렌더링.
- 추가 브라우저 검사: 실제 시작 버튼 진입, 9채·주민 6명, 네 방향 건물, 우물 클릭·가동 중지·재개, 6종 건설 미리보기, 실제 생산·운반, CPU 화면, 모바일 회전과 설정을 통한 복귀.
- 별도 테스트 브라우저에 기존 저장·복구·백업을 넣은 뒤 자동 저장 주기와 설정 동작을 거쳐 세 키의 값이 그대로인지 확인했다. 사용자 브라우저 저장에는 접근하지 않았다.

추가 브라우저 명령은 `node tests/starter-environment-browser.mjs <playwright/index.mjs> <chrome.exe>`다. 증거는 `docs/verification/starter-environment/`에 있다. 최종 실행에서는 실제 캠페인을 120초 진행해 밀 68·물 42·목재 36·판재 24 생산과 운반량 195를 확인했다. 사용자 입력과 실행 타이밍에 따라 생산량은 달라진다. 이미지 요청 오류와 pageerror는 없었다.

화면 검수에서 지면이 건물 기초를 자르는 문제와 주택 굴뚝 연기 위치를 수정했다. 시점별 건물의 세부 형태·픽셀 정렬에는 생성 아트 차이가 남아 있다. 전체 환경 전환이나 출시 아트 품질을 보장하는 검사는 아니다. 빌드는 기존 500KB 초과 청크·경로 정적 분류 안내를 남겼다.

## 확인 범위와 남은 사항

- Windows/macOS 실제 기기에서 이번 묶음을 실행한 것은 아닙니다. 기본 명령은 Bash에 의존하지 않도록 구성했고 검증은 위 Linux 환경에서 수행했습니다.
- 이번 작업에서는 새 아트 검수나 전체 브라우저 플레이 테스트를 반복하지 않았습니다. HTTP 검사와 자동 검사만으로 모든 애니메이션의 시각 품질을 보증하지 않습니다.
- 빌드에는 큰 JS 청크(500KB 이상) 경고와 Vinext의 경로 정적 분류 안내가 있습니다. 빌드는 성공했으며 성능 분할 개선은 남아 있습니다.
- `npm run lint`, 플랫폼별 음향 장치, 저사양/모바일 성능, 장기 게임 밸런스는 이번 이전 작업의 검증 범위가 아닙니다.
- `tests/render-*.mjs`는 이전 환경의 별도 Canvas 도구 경로를 사용합니다. 소스 보존 목적으로 포함했으며 기본 `npm test`에서는 실행하지 않습니다. 이를 사용할 때에는 로컬 Canvas 의존성/경로 조정이 필요합니다.
- 프로젝트는 개발 중인 프로토타입입니다. 기존 문서의 'RELEASE'라는 파일명은 출시 완료 인증을 의미하지 않습니다.

## ZIP 구성 원칙

소스, 사용/보관 중인 자산, 캐릭터 원본과 프롬프트, 기존 테스트, 기획/과거 스크린샷, 외부 자산 출처/라이선스를 포함합니다. 제외한 것은 `node_modules`, `.git` 이력/인증 정보, 빌드 산출물, 임시 실행 캐시 및 `tsconfig.tsbuildinfo`입니다. 의존성은 `npm run setup`, 빌드는 `npm run build`로 재생성합니다.

사용자의 브라우저 localStorage 세이브는 프로젝트 파일이 아니므로 ZIP에 들어 있지 않습니다. `README.md`의 JSON 내보내기/불러오기 절차로 이전합니다.

`docs/EXPORT_MANIFEST.json`은 자기 자신을 제외한 실제 동봉 파일의 크기와 SHA-256을 기록합니다. 원본 커밋, 제외 항목, 파일 보존 검사도 함께 기록합니다.
