# 픽셀 아트 적용 현황

게임 속 시설·주민·환경의 그림은 픽셀 계열이다. 모든 화면 요소가 픽셀 그림인 것은 아니다. 세계 지도의 국경·격자·글자, 버튼의 선 아이콘, 선택 표시·체력 막대는 SVG 또는 렌더러 도형이다.

| 영역 | 현재 적용 |
|---|---|
| 시설 | 건물 106종의 네 방향 본체·생산 상태·실제 재고, 본체 변형을 이용한 파손·복구와 공통 손상 레이어. 확장·보완 24종은 이미지 모델 원화 |
| 환경 | 8개 생태 지형, 네 변 배경, 수목·바위·물가, 도로·철도·관·컨베이어 |
| 주민 | 51종의 게임용 동작·상세 초상화. 반대편 두 방향은 좌우 반전 |
| 운송·상품 | 운송 그림 10종, 상품 80종과 지원 기능 6종 아이콘. 확장·보완 상품 44종은 이미지 모델 원화 |
| 대기·홈·로딩 | 픽셀 배경 3장, 주민 일상 24장(기존 캐릭터 27명), 화면 전환 4장 |
| 세계 지도 | 전용 픽셀 지형 12종과 수도·후보·보유·적대 표식 4종. 이웃 지형을 따라 연결한 지형 이미지와 SVG 국경·격자·글자를 함께 사용 |
| 정보 UI | 글자, 선 아이콘과 상태 도형. 픽셀 일러스트와 함께 사용 |

## 이번에 정리한 잔재

시작 시 쓰이지 않는 옛 GLB 모델 요청이 84건 발생했다. `assets.js`는 이제 픽셀 팩만 읽으며, `models.js`의 구형 입체 건물·임시 상자와 `scene.js`의 비픽셀 경비병 장식 경로를 제거했다. 현재 시설 전체가 게임 진입점에서도 픽셀 그림으로 생성되는지 검사한다. 신규 시설에 작화 등록을 빠뜨리면 임시 입체 모형을 보여 주지 않고 누락을 알린다.

옛 GLB 파일과 이전 화면 원본은 보존 자료다. 현재 게임에서 로딩하지 않는다. `tests/asset-pose.mjs` 등 옛 모델 전용 검사는 보존 자료를 직접 읽으며 현재 게임의 시각 품질 검사가 아니다.

기존 작업 로딩 6장은 매끈한 애니메이션풍이었다. 같은 인물을 픽셀 화풍으로 다시 그리고 광산 공방·관개 온실·설원 철도·항구 배송·숲속 목공·차량 정비를 반영했다. 대기·홈·기본 로딩에는 광산, 설산, 내해 항만과 화물 운송을 보강했다. 화면 원화는 실제 지도 캡처가 아니라 게임 배경을 표현한 일러스트다.

## 운송·시설 동작 보완

1. **운송수단:** 말 다리·바퀴·외륜·노·프로펠러를 원화 부품으로 구운 8프레임과 이동 중 물결을 적용했다. 실제 이동 거리에 맞춰 진행하며 정지·일시정지·카메라 회전으로 걷는 프레임을 진행시키지 않는다. 계류 항공기는 정지한다.
2. **시설 작업:** 실제 도착 이벤트로 항구 3종의 인양 화물을 움직이고, 실제 재고 이동 경로에 관·컨베이어 화물을 표시한다. 수차 등의 회전은 고정된 평면을 쿼터뷰로 투영한다. 극지 항의 북서 화물은 지붕에 가려져 변위를 생략한다.
3. **심한 파손·복구:** 104종 각각의 본체를 나눠 기초를 고정하고 상부를 낮춘다. 공통 균열·잔해와 함께 표시하며 수리하면 원래 실루엣으로 복구한다. 건물별 별도 폐허 원화를 새로 그린 방식은 아니다.

원본 좌표와 재생성은 `art-source/pixel-environment/motion-v10/`, [실제 화면과 검사 결과](verification/environment-motion-20260929/README.md)에서 확인한다.

캐릭터 관절 마감은 51종에 반영했다. 관절 틈·겹침, 장갑·손 조각, 꼬리·날개 분리와 쓰러짐 무릎을 보완했다. [수정 전후와 검증](verification/character-finish-20260929/README.md)에서 확인한다. 원화 부위를 관절로 움직여 구운 프레임이며, 전 프레임을 새로 손작화한 방식은 아니다.

브론의 걷기·운반은 방향별 원화 8자세에 발 디딤 보정을 더한 32프레임이다. 실제 이동 거리에 맞춰 재생하며, 멈추면 양발을 디딘 대기·상자 들기 자세로 바뀐다. 흙·도로·철도·관과 컨베이어의 지면 높이에 발 기준점을 맞춘다. 원화·발 좌표·보폭은 `art-source/pixel-characters/bron-locomotion-v2/manifest.json`에 있다.

작업·공격은 `bron-motion-v1/`의 망치 원화를 사용한다. 작업은 어깨 높이에서, 공격은 머리 위에서 내려친다. 두 반대 방향은 좌우 반전이며, 보행 32프레임은 32장의 독립 원화가 아니다. [브론 동작 비교](http://localhost:5173/character-preview/bron-motion/)에서 확인한다. `roster-v4/bron/rig.json`이 두 원화 묶음을 연결하며 `python scripts/roster_rig.py bron`으로 재생성한다.

나머지 50명도 걷기·운반을 32프레임으로 재생한다. 기존 원화의 신발 형태를 유지하고 발바닥을 기준으로 접지한다. 사람형은 고정 길이 관절로 걷고 켄타로스는 네 발을 교대로 딛는다. 요정·정령은 떠서 이동한다. 원화별 발 좌표는 각 리그의 `contactMotion`에 있으며 `python scripts/pack-cast-locomotion.py`로 재생성한다. 이 50명은 기존 원화 부위를 변형한 동작이며, 브론처럼 별도의 보행 자세 원화를 추가한 방식은 아니다. [캐릭터 보기](http://localhost:5173/character-preview/)에서 인물·방향·행동을 선택한다.

들기·놓기는 51명 모두 각 12프레임의 독립 관절 동작이다. 놓기는 물건을 낮춘 뒤 손을 떼고 대기로 돌아온다. 브론의 대기·들기·놓기 원본 연결은 `bron-handling-v3/rig.json`이다.

사람형 관절 보행은 뒤꿈치 착지·발바닥 지지·발끝 이탈을 구분하고 발목과 신발이 함께 회전한다. 51명의 인사·피격·회전은 대기 자세로 복귀하며, 운반 중 피격에는 화물을 유지하는 별도 자세가 있다. 작업과 공격은 준비·실행·복귀의 속도를 다르게 적용한다. 실행 팩은 8192×1536이며 프레임 위치는 `frames.json`의 `clips`와 `variants`를 읽는다.

**전 캐릭터 동작 작화는 미완료다.** 보행의 체중 이동·발끝 이탈·팔과 다리의 조화 등 시각 품질에는 추가 작업이 필요하다. `authored-actions-v6/`와 `authored-actions-v7/`의 신규 시트는 발 교대·자세 연결·접지 등록이 부족한 미승인 초안이며 게임에 적용하지 않았다. 관절·접지 자동 검사는 자연스러움에 대한 합격 판정이 아니다. 인물별 11개 동작과 네 방향의 남은 작업은 [캐릭터 전체 동작 체크리스트](CHARACTER_ANIMATION_CHECKLIST.md)를 따른다.

사막 유정·습지 나루터·화산 고원 대장간·설원 배송·해안 어업은 일상 그림에 추가했다. 세계 지도 지형과 거점 표식도 전용 픽셀 원화로 교체했다. 지도 원본은 `art-source/world-atlas/`, 재패킹은 `node scripts/pack-world-atlas.mjs`다. 기능 버튼의 선 아이콘은 유지한다.

## 확장 시설·상품과 목축

확장·2차 보완 시설 24종, 상품 44종, 작물 성장 9종에 이미지 모델 원화를 사용한다. 사탕수수·소금·포도·카카오·딸기·박하·호박·참나무는 빈 밭 위에 네 단계 성장 그림을 따로 얹는다. 포도는 선택한 생산법에 따라 적포도·청포도를 표시하며, 건설 메뉴에는 성숙 작물이 보인다.

양봉장은 사각 상자 벌통, 사료 공장은 낮은 사일로와 제분기, 양조장은 큰 숙성통과 압착기로 구분한다. 얕은 광산에는 평지 갱구와 도르래, 풍력 양수기에는 격자 탑·회전자·물통을 사용한다. 회전자·도르래·압착기는 본체와 분리된 부품이다. 상품 아이콘과 지도 재고는 같은 원화를 쓰며, 기존 상품 순서는 유지한다.

양·젖소·오리는 네 방향의 서기·걷기·먹기 그림을 재생한다. 벌은 개별 날갯짓과 비행 경로를 사용한다. 생산이 멈추면 가축은 서고 벌은 숨으며, 일시정지하면 동작도 멈춘다. 가축 수와 움직임은 장식이며 별도 축산 개체 시뮬레이션은 아니다.

원화와 패킹 명세는 `art-source/pixel-environment/farm-v11/`와 `farm-v12/`에 있다. 재생성은 `node scripts/pack-farm-refresh.mjs` → `node scripts/pack-resource-icons.mjs` 순서다. `farm-v9/`는 이전 원본이며 재실행해도 최신 원화의 등록을 덮어쓰지 않는다.

[농장](http://localhost:5173/production-preview.html?group=farmcrops), [목축](http://localhost:5173/production-preview.html?group=ranch), [공방](http://localhost:5173/production-preview.html?group=farmworks), [얕은 광산·양수기](http://localhost:5173/production-preview.html?group=farmsupport)에서 네 방향과 생산 상태를 비교한다. 상품은 [일러스트 테스트](http://localhost:5173/art-preview.html)의 자원 보기에서 확인한다.

남은 한계:

- 작물은 성장 단계별 그림을 바꾸며, 연속적으로 자라거나 잎이 개별적으로 움직이지 않는다.
- 가축은 8개 자세를 조합한 짧은 반복 동작이다. 연속 방향 전환이나 서로 피하는 행동은 없다.
- 일부 작업 부품은 공통 도구 아틀라스를 쓰며, 초콜릿 솥을 젓는 전용 동작은 없다.
- 연못·목초지·야생 클로버는 작업 주기가 없어 본체만 표시한다.

## 확인·재생성

- 홈의 **마을의 하루**에서 일상 24장과 전환 4장을 분류·미리보기로 고를 수 있다. 일상 그림마다 주인공이 다르며 실제 캐릭터 이름을 표시한다. 홈 진입 시 35% 확률로 일상 그림을 선택한다.
- 실제 로딩이 8초를 넘으면 일상 그림으로 교체하며 완료된 게임 진입은 지연시키지 않는다. 메뉴 전환 그림은 520ms 이내이며 건너뛰기와 동작 줄이기를 지원한다.
- 원본·프롬프트·패킹 목록: `art-source/screen-concepts/2026-09-29/{pixel-refresh,daily-expansion}/manifest.json`.
- 실행용: `public/assets/screens/{pixel-v2,daily-v3}/`. `node scripts/pack-screen-art.mjs`로 본문과 미리보기를 다시 만든다.
- 자동 검사: `npm test`, `npm run typecheck`, `npm run build`. 확장 그림의 픽셀·시점·상태 검사는 `tests/farm-art.mjs`.
- 확장 그림 화면 캡처: `node tests/farm-art-browser.mjs <playwright/index.mjs> <chrome.exe>` → `docs/verification/expansion-art-20260929/`.
- 실제 화면 검사: `node tests/start-screens-browser.mjs <playwright/index.mjs> <chrome.exe>`.
- 게임 초기화 없는 화면 미리보기: `/screen-preview`. 컴포넌트 검사: `node tests/screen-components-browser.mjs <playwright/index.mjs> <chrome.exe>`.
- 화면 캡처와 검사 결과: `docs/verification/start-screens/`. 이전 홈·GLB 요청 측정: `docs/verification/pixel-refresh/`.
